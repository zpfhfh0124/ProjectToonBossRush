# 게임 로직 설계 — 전체 게임 플로우 (GameFlowManager)

> 작성일: 2026-09-20
> 전제: 플레이어 이동/카메라(1주차)는 완료, 전투 콤보·회피·히트박스·히트스탑·보스 `Idle→Telegraph→Attack→Recover→Stagger` 상태머신은 이미 프로젝트에 존재(`PlayerController`, `PlayerCombat`, `HitboxController`, `HitStop`, `ToonHitFlash`, `CameraShake`, `Health`, `BossStateMachine`, `BossAttackPatternSO`) — 이 문서는 그 위에 얹는 **상위 진행 흐름**만 다룬다.

## 1. 왜 필요한가

지금까지 만든 시스템들은 각자 완결돼 있지만 서로를 모른다 — `BossStateMachine`은 자기가 죽으면 `Health.OnDied`를 쏘기만 하고, 그다음에 무슨 일이 일어나야 하는지(다음 보스로 넘어가는지, 클리어 화면이 뜨는지)는 아무도 모르는 상태였다. 씬에 보스가 몇 체든, 플레이어가 죽든 말든, "지금 몇 번째 보스 차례고 언제 게임이 끝나는지"를 관리하는 코드가 없었다는 뜻. `GameFlowManager`가 그 자리를 채운다.

기획서 4장(핵심 루프) 그대로: **시작 → 아레나 진입 → 보스 A → 보스 B → 클리어 화면**. 여기에 플레이어 사망 시 게임오버, 클리어 화면에 표시할 통계(격파 시간/피격 횟수/매칭 카운터 성공 횟수, 기획서 4장·7장) 수집까지 포함한다.

## 2. 상태 흐름

```
Intro ──(introDelaySeconds)──▶ BossFight[0] ──보스0 Health.OnDied──▶ Transition
                                    │                                    │
                                    │                      (transitionDelaySeconds)
                                    │                                    ▼
                                    │                              BossFight[1] ──보스1 Health.OnDied──▶ Clear
                                    │
                              플레이어 Health.OnDied (어느 시점이든)
                                    │
                                    ▼
                                GameOver
```

- 인카운터가 N개면 위 패턴이 N번 반복되고, 마지막 보스가 죽으면 `Transition` 없이 바로 `Clear`.
- `GameOver`/`Clear`는 종단 상태 — `RunResult`를 만들어 `OnRunComplete` 이벤트로 한 번 흘려보내고 멈춘다. 다시 시작하려면 `StartRun()`을 호출(재도전 버튼이 붙일 자리).

## 3. 컴포넌트 구조

### `GameFlowManager` (신규, `Assets/Scripts/ToonBossRush/Core/GameFlowManager.cs`)

씬에 빈 GameObject(`GameFlow`)에 붙이는 싱글턴. 책임은 딱 세 가지뿐이고, 그 이상은 하지 않는다(전투 세부 규칙은 여전히 `PlayerCombat`/`BossStateMachine`이 담당):

1. **인카운터 진행** — `encounters` 리스트(순서대로 싸울 보스들)를 하나씩 활성화하고, 활성 보스의 `Health.OnDied`를 구독해 다음으로 넘어감.
2. **런 종료 판정** — 플레이어 `Health.OnDied` → `GameOver`, 마지막 인카운터 격파 → `Clear`.
3. **통계 수집** — 격파 시간(`Time.time` 기준, Intro 끝나는 시점부터), 피격 횟수(전투 중 `Health.OnDamaged` 발생 횟수), 매칭 카운터 성공 횟수(`ReportMatchingCounterSuccess()` 훅 — 아직 아무도 호출 안 함, 텔레그래프 매칭 카운터 구현 시 그 시스템이 이 메서드만 호출하면 됨).

### `BossEncounter` (GameFlowManager 내부의 직렬화 가능한 데이터 클래스)

```csharp
public string displayName;      // HUD용 보스 이름 표시 자리(아직 HUD 없음, 기록만)
public BossStateMachine boss;
public GameObject rootToActivate; // 비우면 boss.gameObject를 그대로 활성/비활성 대상으로 씀
```

인카운터 = "죽으면 다음으로 넘어가는 단위"를 최대한 느슨하게 잡았다. 지금은 보스 2체를 각각 하나의 `BossEncounter`로 넣으면 되고, 기획서 12장 리스크대로 일정이 빠듯해져서 **"보스 2체" 대신 "보스 1체 3페이즈"로 스코프를 줄이더라도** `encounters` 리스트를 길이 1로 두고 페이즈 전환은 `BossStateMachine` 내부에서 처리하면 됨 — `GameFlowManager`는 "그 보스의 최종 `Health`가 죽었는가"만 보기 때문에 이 구조 변경 없이 그대로 대응된다.

### 기존 파일에 추가한 것 (기존 로직은 그대로, 딱 필요한 것만 얹음)

- **`BossStateMachine.cs`**
  - `public Health Health => _health;` — `GameFlowManager`가 `OnDied`를 구독하려면 필요. 지금까지 `_health`는 완전히 private이라 외부에서 보스가 죽었는지 알 방법이 없었음.
  - `public void BeginEncounter()` — 지금은 `EnterIdle()`과 동일. 나중에 "보스 등장" 연출(카메라 팬, 등장 애니메이션)을 붙일 자리를 미리 만들어둔 것 — `GameFlowManager` 쪽 호출 코드는 안 바꿔도 됨.
  - `public void ResetEncounter()` — 재도전 시 체력·상태·패턴 재사용 쿨다운을 전부 초기화. 지금까지는 "다시 시작"이라는 개념 자체가 없어서 이 메서드가 없었음.
- **`PlayerController.cs`**
  - `public void Teleport(Vector3 position, Quaternion rotation)` — `CharacterController`가 켜진 채로 `transform`을 직접 옮기면 다음 프레임 충돌 보정이 어긋날 수 있어서, 잠깐 꺼서 옮기고 다시 켬. 회피/낙하 관련 내부 상태도 같이 초기화(회피 중 사망 → 재도전으로 이어져도 이상한 잔여 상태 없이 시작).

## 4. 씬 세팅 방법 (경태님이 Unity 에디터에서 할 일)

1. 빈 GameObject 생성 → 이름 `GameFlow` → `GameFlowManager` 컴포넌트 추가.
2. Inspector에서:
   - `Player Health` / `Player Controller` — 플레이어 오브젝트에 붙어 있는 `Health`/`PlayerController` 드래그.
   - `Player Spawn Point` — 씬의 `SpawnPoint_Player`(이미 `StageBlockoutBuilder.cs`가 만들어둔 것) 드래그.
   - `Encounters` — 리스트에 보스 수만큼 항목 추가, 각 항목의 `Boss`에 해당 보스의 `BossStateMachine` 드래그. `Root To Activate`는 보통 비워둬도 됨(보스 오브젝트 자체를 켜고 끔).
3. **중요**: 보스 GameObject는 씬 로드 시점에 **활성 상태**로 둔 채로 시작해야 함 — `GameFlowManager.Start()`가 시작하자마자 비활성화하지만, `Awake()`(→ `Health` 이벤트 구독)는 그 전에 이미 한 번 실행돼야 하기 때문. 씬 저장할 때 보스 오브젝트를 굳이 비활성화해두지 않아도 됨(런타임에 자동으로 처리됨).
4. Play 모드로 확인: 콘솔에 `[GameFlow]` 로그가 뜨는지(현재는 HUD가 없어서 클리어/게임오버 결과를 로그로만 확인 — 3번째 항목 참고).

## 5. 지금 일부러 안 만든 것 (다음 단계로 미룸)

이번 라운드에서 "전체 게임 플로우"에만 집중하기로 했고, 아래는 각자 별도 설계/구현이 필요해서 훅만 열어두고 손대지 않음:

- **HUD/클리어 화면 UI**: `OnStateChanged`/`OnRunComplete` 이벤트를 구독하는 실제 Canvas가 없음. 지금은 `CompleteRun()`에서 `Debug.Log`로만 통계를 확인 가능.
- **텔레그래프 매칭 카운터**(기획서 5장): `BossStateMachine.EnterTelegraph()`의 TODO 주석 그대로, 색상 필드·판정 로직 미구현. 구현되면 성공 판정 시 `GameFlowManager.Instance.ReportMatchingCounterSuccess()`만 호출하면 통계에 바로 반영됨.
- **원거리 마법 투사체**: 아직 코드 없음. `GameFlowManager`와는 직접 연동점이 없음(플레이어 공격 시스템 쪽 확장).
- **PlayerCombat 쪽 잔여 상태 초기화**: 재도전 시 `PlayerController.Teleport()`로 이동/회피 상태는 초기화되지만, `PlayerCombat`의 콤보 인덱스·공격 잠금(`_isAttacking`)은 손대지 않음 — 사망 시점에 마침 공격 애니메이션 중이었다면 재도전 후 첫 입력이 무시될 수 있는 자잘한 엣지케이스가 남아 있음. 실제 플레이 테스트에서 걸리면 `PlayerCombat`에 `ResetCombatState()` 하나 추가하는 정도로 쉽게 고칠 수 있음.

2. 보스 2체(또는 페이즈 데이터)가 준비되면 `encounters`에 추가 — 코드 변경 없이 리스트만 늘어남.
